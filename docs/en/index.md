# OSIP Knowledge Base

This repository is the canonical source of OSIP engineering knowledge. The published MkDocs site is a generated view; Markdown, diagrams, ADRs, research, templates, and supporting artifacts in Git remain authoritative.

## Working model

1. Define the architecture.
2. Record the decision in an ADR when it is consequential.
3. Write the relevant specification.
4. Implement and test against the documented decision.

## Structure

- **Foundation** defines why OSIP exists and its enduring principles.
- **Strategy** records product direction, milestones, and roadmap.
- **Architecture** specifies platform models and cross-cutting design.
- **Standards** governs documentation and engineering conventions.
- **Knowledge** indexes curated findings and reusable guidance.
- **Collaboration** explains how contributors propose, review, and maintain change.
- **Operations**, **AI**, **Product**, and **Reference Designs** cover their respective domains.

Artifacts that need to live beside documentation have dedicated top-level folders: `adr/`, `research/`, `diagrams/`, `bom/`, `installer/`, `deployment/`, `templates/`, `scripts/`, and `assets/`.
