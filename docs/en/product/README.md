# Product

Product documents turn strategy into bounded, testable increments. Each feature or release defines the target user, problem, supported installation scope, user journey, privacy/security impact, non-goals, acceptance criteria, owner, support path, and link to relevant ADRs.

The first product boundary is Installer Edition: a qualified installer can commission and service a supported local-first installation without undocumented founder knowledge. Reference-apartment findings become product requirements only after they are generalized and validated.
