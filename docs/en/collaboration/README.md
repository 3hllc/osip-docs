# Collaboration

OSIP uses a docs-as-code workflow. Contributors propose a change in the canonical document, add or update an ADR when the decision is significant or difficult to reverse, and submit the change for review with linked diagrams, evidence, and operational implications.

Reviews verify that the change preserves Charter principles, does not create a second source of truth, names ownership and assumptions, and has testable acceptance or decision criteria. A disagreement that affects architecture is recorded as an ADR proposal rather than resolved only in chat. Accepted ADRs preserve history; a later decision supersedes them explicitly.

Document owners keep specifications current as implementation and production evidence change. Research is not silently promoted to policy: it is linked from the accepting decision or specification.
