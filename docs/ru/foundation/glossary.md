# Глоссарий

## Назначение

Этот глоссарий устанавливает предпочтительные значения терминов во всех спецификациях OSIP, ADR, reference designs и материалах инсталлятора. Определённый здесь термин нельзя переопределять локально без явной документированной причины. Названия продуктов и специфичная для вендора лексика находятся в документе интеграции, если термин не нужен для понимания контракта OSIP.

## Термины платформы

| Термин | Значение в OSIP |
| --- | --- |
| **OSIP** | Open Spatial Intelligence Platform: Local First-платформа и набор повторяемых практик для пространственно осведомлённых сред. Это не продукт одного вендора и не синоним Home Assistant. |
| **Local First** | Обязательные функции продолжаются в доверенной локальной среде при потере WAN. Облако может улучшать функцию, но не быть её единственным путём управления, если она явно не классифицирована как cloud-dependent. |
| **Cloud Enhanced** | Необязательная для нормальной локальной работы облачная возможность: удалённый доступ, резервное копирование по согласию, сведения о парке или ресурсоёмкий inference. |
| **Reference apartment** | Реальная среда валидации 165 м² для проверки проектов, commissioning, recovery после отказов и доказательств до productization паттерна. |
| **Reference deployment** | Реальная среда для проверки профиля возможностей OSIP. Reference Apartment — первое такое развёртывание, но оно не задаёт охват платформы или будущие поддерживаемые типы пространств. |
| **Installer Edition** | Будущий повторяемый пакет поставки, созданный из проверенных reference designs и включающий установку, ввод в эксплуатацию, поддержку и материалы приёмки. |
| **Adapter** | Компонент преобразования на границе провайдера интеграции; не является общим доменным понятием OSIP. |
| **Integration boundary** | Интерфейс, на котором внешние payload, identity, credentials, доступность и ошибки нормализуются до потребления общими сервисами OSIP. |

## Термины модели и взаимодействия

| Термин | Значение в OSIP |
| --- | --- |
| **Spatial model** | Устойчивое представление пространств, зон, объектов, отношений и контекстного смысла среды. |
| **Digital twin** | Проекция релевантного физического и контекстного состояния с учётом времени и указанием источника. Это не полная копия payload вендора и не замена source-of-truth систем. |
| **Site** | Верхняя физическая и операционная область развёртывания OSIP: residence, office, hotel, campus или industrial location. |
| **Asset** | Физическая или виртуальная сущность — «актив» — со стабильным `asset_id` OSIP: например, sensor, HVAC unit, door, lighting circuit, camera или логический engineering asset. Внешние идентификаторы — привязки, а не его устойчивая идентичность. |
| **Device** | Полевой endpoint или controller, представленный как актив OSIP. Его радио-, vendor- и integration-идентификаторы являются атрибутами, а не устойчивой доменной идентичностью. |
| **Capability** | Нормализованная возможность устройства или сервиса, например sensing присутствия, диммирование, состояние контакта или измерение температуры. |
| **Provider** | Ограниченный провайдер интеграции, отображающий внешний продукт, протокол или API в активы OSIP, возможности, канонические события и команды. Home Assistant — один из возможных провайдеров. |
| **Binding** | Явная привязка между активом OSIP и внешней идентичностью провайдера, включающая роль управления, работоспособность, происхождение и жизненный цикл. |
| **Observation** | Факт, сообщённый источником в момент времени, например температура или нажатие кнопки. Наблюдения могут быть поздними, дублированными, некорректными или устаревшими. |
| **State projection** | Текущая интерпретация, выведенная из наблюдений и команд. Она несёт источник, timestamp и качество и не заявляет свежесть, которую платформа не может установить. |
| **Command** | Запрошенное действие с указанием источника. Принятие брокером не означает завершение; завершение доказывается наблюдаемым результатом или документированным acknowledgement. |
| **Intent** | Запрошенный результат для пространства или актива, например поддержание комфорта во время встречи. Намерение разрешается в план исполнения, соответствующий политике, а не напрямую управляет именованными устройствами. |
| **Execution plan** | Атрибутируемый выбор, одобренный политикой: допустимые активы, возможности, привязки провайдеров, команды, резервные пути и проверка, необходимые для выполнения намерения. |
| **Event** | Неизменяемая запись о произошедшем или изменившемся. У событий есть версионированные контракты, владелец, время, источник и классификация. |
| **Context** | Смысл, выведенный из пространственных, временных, поведенческих и системных фактов, например «активность в зоне кухни после заката». |

## Термины связности

| Термин | Значение в OSIP |
| --- | --- |
| **MQTT broker** | Локальный client-server publish/subscribe транспорт, первоначально используемый для сообщений OSIP. MQTT не является доменной моделью OSIP и не является mesh-топологией. |
| **Topic** | MQTT-имя маршрутизации транспорта. Topic недостаточен как семантическая документация: смысл задаёт версионированный контракт события или команды. |
| **Zigbee mesh** | Маломощная радио-сеть между endpoint Zigbee, роутерами и координатором. Она отделена от MQTT и входит в OSIP через адаптер интеграции. |
| **Coordinator** | Корень сети Zigbee, подключённый к integration host или gateway. Это актив commissioning/recovery, а не сервис ядра OSIP. |
| **Router** | Zigbee-устройство, ретранслирующее радиотрафик. Устройство должно быть проверено как роутер; питание от сети само по себе не гарантирует полезную ретрансляцию. |
| **End device** | Конечная точка Zigbee, обычно батарейная, которая, как правило, не ретранслирует mesh-трафик. |

## Термины управления

| Термин | Значение в OSIP |
| --- | --- |
| **ADR** | Architecture Decision Record: устойчивая запись значимого решения, его контекста, последствий и статуса. ADR не является заметкой встречи. |
| **Decision log** | Индекс решений, включая небольшие или временные, не оправдывающие ADR. При наличии ADR он на него ссылается. |
| **Assumption** | Утверждение, временно считающееся истинным для продолжения работы. Оно указывает доказательства проверки и последствия ложности. |
| **Constraint** | Обязательное ограничение, введённое безопасностью, законом, средой, бюджетом, интероперабельностью, инфраструктурой или ранее принятым решением. |
| **Risk** | Неопределённое будущее событие с возможным отрицательным эффектом. У риска есть вероятность, воздействие, владелец, митигация и триггер. |
| **Open question** | Неизвестное, значимое для решения, с указанным следующим шагом. Это не допущение и не запись реестра рисков. |

## Правила именования

Используйте эти термины в заголовках, event-контрактах и диаграммах. Предпочитайте точное «Zigbee integration adapter» расплывчатому «bridge» и «наблюдаемое завершение» формулировке «MQTT доставил». Новый междокументный словарь предлагается pull request, одновременно обновляющим этот глоссарий и релевантную спецификацию.
