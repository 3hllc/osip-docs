# Архитектура

Этот раздел описывает платформу до реализации. OSIP — операционный control plane для физических пространств, а не панель управления умным домом и не дистрибутив Home Assistant. Он владеет пространственной моделью, моделью активов и возможностей, политиками, намерениями и операционной моделью; провайдеры интеграций, такие как Home Assistant, MQTT-мосты, BACnet, KNX и API производителей, остаются заменяемой инфраструктурой ниже его канонической границы.

Прочитайте [Модель физических активов](physical-asset-model.md) для иерархии объекта, пространства и актива, [Провайдеры интеграций](integration-providers.md) для канонической границы и [Намерения, политики и исполнение](intent-policy-and-execution.md), чтобы понять, как запрошенный результат становится контролируемым действием. [Edge Runtime](edge-runtime.md) определяет локальную непрерывность, а [Парк и control plane](fleet-control-plane.md) — работу с несколькими объектами без включения в критический путь.

[Сквозная операционная модель](end-to-end-operating-model.md) показывает полный путь высокого уровня: от физических устройств через провайдеров интеграций и канонические контракты OSIP к constrained spatial reasoning, детерминированному исполнению и наблюдаемому результату.

Спецификация [Zigbee Mesh и MQTT-мост](zigbee-mesh-and-mqtt-bridge.md) отделяет физическую Zigbee-сеть устройств от MQTT transport. Она не делает Zigbee2MQTT или MQTT доменной моделью OSIP.
