# Радар технологий

## Назначение

Радар фиксирует технологии, обсуждавшиеся для OSIP, не принимая их за необратимые решения платформы. Кольцо выражает намерение внедрения, а не одобрение продукта. До production-использования каждой записи всё ещё нужны анализ версии, лицензии, поддержки, безопасности, операций и заменяемости.

## Кольца

| Кольцо | Значение |
| --- | --- |
| **Adopt** | Принятая архитектурная база с учётом ADR и эксплуатационных ограничений. |
| **Trial** | Кандидат для проверки в reference apartment. |
| **Assess** | Стоит исследовать; обязательства по интеграции нет. |
| **Hold** | Не вводить, пока не устранено заявленное опасение. |

## Начальный радар

| Область технологий | Кольцо | Позиция OSIP |
| --- | --- | --- |
| MQTT | Adopt | Начальный локальный event backbone; контракты остаются независимыми от транспорта. |
| Home Assistant | Adopt | Начальная платформа интеграции; никогда не ядро домена OSIP. |
| Zigbee с заменяемым адаптером | Trial | Проверить RF-проект, жизненный цикл поддерживаемых устройств, commissioning и recovery mesh в reference apartment. |
| Zigbee2MQTT | Trial | Сильный начальный кандидат адаптера; raw topic model остаётся вне контрактов OSIP. |
| Docker / Docker Compose | Trial | Кандидат для локальной упаковки; оценить upgrade, backup, секреты и workflow оператора. |
| Grafana | Trial | Кандидатный слой представления наблюдаемости; оценить локальную работу и контроль доступа. |
| Matter / Thread | Assess | Оценивать по возможность, зрелости, commissioning UX и доказательствам local control, а не рыночным заявлениям. |
| ESPHome и собственный MCU firmware | Assess | Оценивать только когда определённую возможность нельзя обеспечить поддерживаемыми продуктами. |
| Edge-хост класса Intel N100 | Assess | Кандидат для локальных сервисов; проверить вычисления, хранение, тепло, питание и обслуживаемость. |
| Узел класса Raspberry Pi | Assess | Кандидат для ограниченных edge-ролей, не предполагаемая универсальная среда. |
| InfluxDB и PostgreSQL | Assess | Оценивать отдельно для telemetry/history и устойчивой реляционной конфигурации/состояния. |
| Прямые cloud-only API устройств | Hold | Несовместимы с Local First без документированного локального деградированного пути. |

## Периодичность review

Радар рассматривается на каждом reference-design milestone и перед релизом Installer Edition. Переход Trial или Assess в Adopt требует доказательств и, если решение архитектурное, ADR. Технологию можно удалить без изменения платформы, если её граница адаптера и контракта соблюдена.
