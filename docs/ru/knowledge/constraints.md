# Ограничения

## Назначение

Ограничения — неоспоримые или действующие сейчас условия, формирующие пространство решений. В отличие от предпочтений, изменение ограничения требует новых полномочий, доказательств или заменяющего решения. Проект называет используемые ограничения, чтобы последующие изменения оценивались намеренно.

## Текущие ограничения

| ID | Ограничение | Источник или обоснование | Архитектурный эффект |
| --- | --- | --- | --- |
| C-001 | Существенная автоматизация и управление устройствами продолжаются в доверенной локальной среде при потере WAN. | Принцип Local First. | Основные identity, пути управления, брокер, адаптеры интеграции и необходимое состояние не могут зависеть только от облака. |
| C-002 | Облачные capability дополнительны и явно классифицированы. | Принцип Cloud Enhanced. | Удалённый доступ, backup, аналитика и ИИ используют облако только с определённым деградированным локальным режимом и границей конфиденциальности. |
| C-003 | Доменные контракты независимы от вендоров и форматов topic отдельных адаптеров. | Принцип Vendor Agnostic. | Интеграции проходят через адаптеры; payload вендора не становятся общим API или пространственной моделью. |
| C-004 | Документация — версионированный проверяемый исходник в Git; опубликованный сайт генерируется из него. | Docs as Code и ADR-0000. | Markdown, текстовые диаграммы, ADR и валидация — часть поставки; правки сгенерированного сайта не авторитетны. |
| C-005 | Чувствительные credentials, ключи сети, backup устройств и персональные данные не коммитятся в Git. | Принцип безопасности и конфиденциальности. | Секреты хранятся во внешнем контролируемом хранилище; документы содержат только процедуры и редактированные примеры. |
| C-006 | Начальная платформа проверяется реальной reference apartment 165 м² до представления как повторяемого продукта инсталлятора. | Product roadmap. | Нужны физические доказательства, записи commissioning и тесты recovery, а не только имитация успеха. |
| C-007 | Значимое для безопасности управление предоставляет ручной override и консервативное поведение при отказе. | Принцип безопасности. | Интеграции актуаторов требуют hazard analysis, контроля доступа, наблюдаемости и определения безопасных состояний. |

## Контроль изменений

Предлагаемое изменение ограничения указывает затронутые ADR, спецификации, reference designs и тесты. Оно рассматривается как архитектурное решение, а не включается в implementation pull request. Временные исключения указывают свой охват, компенсирующую меру, срок действия или триггер review и владельца.
