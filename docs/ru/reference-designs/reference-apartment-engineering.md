# Инженерный проект reference apartment

## Назначение

Reference apartment площадью около 165 м² — первая среда физической валидации OSIP. В ней проверяется повторяемый системный проект, а не собираются привлекательные устройства. Квартира одновременно является инженерной лабораторией, демонстрационной средой, репетицией commissioning и источником доказательств для Installer Edition.

## Инженерный охват

Проект фиксирует требования и интерфейсы для инженерного пространства подвесного потолка, сети и питания, освещения и затенения, доступа и безопасности, защиты от протечек, HVAC (включая VRF и/или тепловой насос, потолочные fan coil, водяной тёплый пол), увлажнения и осушения, датчиков, камер, голоса и одобренной робототехники. Указанная система — охват проектирования, а не одобренная покупка устройства.

## Пакеты проектных работ

| Пакет | Требуемые доказательства |
| --- | --- |
| Пространственная основа | Именованные комнаты, зоны, соглашение координат, модель мебели/объектов, классификация конфиденциальности и правило контроля изменений. |
| Инженерные системы | Реестр интерфейсов, безопасные состояния, ручные override, зависимости электрики и воды, владение актуаторами и последовательность commissioning. |
| Сеть и радио | Зоны доверия, проводное/беспроводное покрытие, размещение координатора, обоснование Zigbee-роутеров, поведение при отказе и приёмочный обход. |
| Матрица устройств/capability | Требуемая capability, место, адаптер, стабильная identity, зависимость от питания/сети, health-сигнал, поддерживаемый жизненный цикл и fallback. |
| Локальная среда выполнения | Размещение сервисов, поведение при потере питания, цель backup/restore, путь авторизованного доступа, мониторинг и план upgrade/rollback. |
| Пользовательский опыт | Явные задачи пользователя/инсталлятора, ручные органы управления, объяснимость значимой автоматизации, границы согласия и доступность. |

## Этапы commissioning

Commissioning идёт упорядоченными слоями: инфраструктура и питание; сеть/время; локальная среда выполнения; питаемые радио-роутеры; оконечные устройства и адаптеры инженерных систем; нормализованные контракты; автоматизация; затем необязательные ИИ-сценарии. Каждый этап имеет зафиксированные тесты. Потеря WAN, перезапуск адаптера, потеря роутера, замена устройства, восстановление из backup и безопасный ручной override — обязательные демонстрации для затронутых capability.

## Правило повторяемости

Обходное решение, специфичное для квартиры, не является продуктовым паттерном. Каждый принятый паттерн указывает время установки, зависимости, инструменты, навыки, доказательства, бремя обслуживания, процедуру замены и условия, когда его нельзя применять. Неразрешённые вариации создают открытый вопрос или риск, а не недокументированное суждение инсталлятора.
